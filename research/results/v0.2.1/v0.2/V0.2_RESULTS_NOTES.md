# Benchmark v0.2 Results — OOD Significance Achieved

**The question this expansion was built to answer:** does growing the OOD subset from 15 to 50
queries (per the power analysis in `research/paper/PUBLICATION_ROADMAP.md`, citing Card et al.
2020) give the baseline-vs-tuned OOD detection comparison enough statistical power?

**Answer: yes, decisively.**

| | v0.1 (n=15) | v0.2 (n=50) |
|---|---:|---:|
| Baseline OOD rejection rate | 26.7% (4/15) | 34.0% (17/50) |
| Tuned OOD rejection rate | 46.7% (7/15) | 68.0% (34/50) |
| Discordant pairs | 3 | 17 |
| Exact McNemar's p-value | 0.25 | **0.000015** |
| Statistically significant (α=0.05) | **No** | **Yes** |

All 17 discordant pairs in v0.2 favor the tuned detector (0 favor the baseline) — a maximally
one-sided result, which is exactly what makes even a modest-looking sample size produce a very
small p-value under McNemar's test.

## Full pipeline re-run against v0.2 (isolated in `research/results/v0.2/`, v0.1 untouched)

1. **`reproduce_baseline_v0_2.js`** — frozen `cli/search.js` against 209 queries: non-OOD
   accuracy 75.5% (120/159), OOD rejection 34.0% (17/50).
2. **`build_folds_v0_2.js`** — same seed (42), same stratification; 10 OOD per fold now
   (vs. 3 in v0.1).
3. **`build_query_scores_v0_2.js`, `run_hybrid_v0_2.js`** — nested-CV hybrid fusion: non-OOD
   accuracy 79.3% (std 5.7pp), all 5 folds selected α=0.5 (more stable than v0.1's mixed 0.3/0.5).
4. **`build_candidates_v0_2.js`, `build_reliability_features_v0_2.js`** — hybrid OOD mean
   top1_score dropped to 0.7527 (vs. 0.8411 on v0.1), widening the gap from CORRECT's 0.98 —
   itself a sign the larger OOD set is, if anything, a cleaner test of the same phenomenon.
5. **`run_selective_prediction_v0_2.js`** — OOD detection AUROC improved 0.867→**0.901**, pooled
   F1 improved 0.500→**0.716** (precision 0.756, recall 0.68, 34/50 correctly rejected). Ambiguity
   detection F1 improved 0.310→**0.496**, though AUROC slightly decreased (0.784→0.723) —
   reported honestly, not cherry-picked; a larger, more diverse ambiguous set (including
   deliberately adversarial cases like the `tar` tokenization-gap query) makes margin-alone
   detection harder in AUROC terms even as the tuned-threshold F1 improves.
6. **`run_statistical_analysis_v0_2.js`** — the significance test above.

## What this changes in the paper's claims

Per the Phase 17 decision gate, the OOD result had to be reported as "large but not statistically
confirmed" (p=0.25, n=15). **That caveat is now resolved for the v0.2 benchmark**: the OOD
detection improvement is statistically significant (p=0.000015, n=50). The manuscript and final
report should be updated to reflect this upgraded claim, while still being explicit that this
result is reported on `termassist_bench_v0.2`, a benchmark whose new queries were authored and
adjudicated by an AI agent under human direction (disclosed in
`research/datasets/v0.2_ADJUDICATION_REPORT.md`) — not silently presented as identical in
provenance to v0.1's original queries.

## What did not change

The core hybrid-vs-BM25 accuracy comparison, the calibration results, the safety evaluation, and
the functional evaluation were not re-run against v0.2 in this pass (out of scope for this
specific request, which targeted the OOD/ambiguity statistical-power question). v0.1 remains the
benchmark of record for those results.
